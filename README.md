# WDTT Tailscale Gateway для Home Assistant OS — экспериментальная сборка 0.3.0

## Что внутри

Локальный HAOS add-on `wdtt_tailscale/`. Использует Go-демон `wdttd` из
[cWDTT/WDTT-OpenWRT](https://github.com/cWDTT/WDTT-OpenWRT), совместимый с
оригинальной архитектурой
[amurcanov/proxy-turn-vk-android](https://github.com/amurcanov/proxy-turn-vk-android).
Сборка скачивает исходники `wdttd` по зафиксированному upstream-коммиту
`b10e1506f17322061ae9ccd7546ca6fd015776ce` и компилирует их (GPLv3); бинарника в архиве нет.

**Статус: экспериментальный прототип; не проверен на реальном HAOS, Tailscale и
VPS.** Python-контроллер протестирован локально; полноценная работа WDTT-сети,
AppArmor/capabilities, сборка Go при установке и подключение к вашему VPS пока
не проверены. НЕ использовать как единственный способ удалённого доступа.

## Установка в HAOS

1. Сделайте резервную копию Home Assistant; проверьте локальный доступ к HAOS
   через IP из домашней сети, минуя Tailscale.
2. Распакуйте **папку** `wdtt_tailscale` из ZIP в `/addons/wdtt_tailscale/` на HAOS
   (например, через SSH/Samba). `config.yaml` должен оказаться по пути
   `/addons/wdtt_tailscale/config.yaml`.
3. Home Assistant → Настройки → Дополнения (или Приложения) → Магазин →
   меню ⋮ → **Проверить обновления**. Появится локальное дополнение
   `WDTT Tailscale Gateway (experimental)`.
4. Установите аддон: Docker-сборка **потребует интернет и доступ к GitHub/Go modules**.
   Поддерживаются `amd64` и `aarch64`; скачивание может не работать при белых списках.
5. Сначала оставьте `connection_mode: off` и `route_tailscale: false`.
6. Для проверки WDTT заполните `peer` (VPS `IP:PORT`), `password`, `vk_hashes`
   (до четырёх VK ссылок `/call/join/...` либо хешей), `device_id` (стабильный ID),
   `connection_mode: always`, **но всё ещё** `route_tailscale: false`.
   Запустите аддон и проверьте логи `wdttd` на статус `connected`.
7. Если WDTT поднимается и есть **локальный** доступ, переключите **в настройках
   существующего Tailscale-аддона** `userspace_networking: false`. Перезапустите
   Tailscale и убедитесь, что интерфейс `tailscale0` есть. Это может временно
   прервать удалённое подключение.
8. Только после этого выставьте `route_tailscale: true`. Проверьте наличие
   маршрута по метке через `wg-wdtt`. Контроллер тестирует TCP через
   VPN и удаляет правило, если тест не прошёл.
9. Переведите `connection_mode: auto`: при последовательных сбоях прямого TCP
   подключения к контрольным адресам активируется WDTT, после устойчивого
   восстановления выключается.

### Параметры

| Опция | Значение |
|---|---|
| `connection_mode` | `off`, `always`, `auto` |
| `peer` | Адрес VPS `IP:PORT` (перенести из WDTT-профиля) |
| `password` | Пароль WDTT; хранится в настройках аддона |
| `vk_hashes` | 1–4 VK call join хеша/ссылки через запятую |
| `device_id` | Постоянный идентификатор устройства. **Новый девайс** на VPS |
| `turn_transport` | `udp` или `tcp`; возможность TCP зависит от клиента/релея |
| `obfs_mode` | `audio` или `video` (маскировка под медиатрафик) |
| `go_dns` | `doh-yandex`, `doh-cloudflare` или `yandex` для API VK |
| `route_tailscale` | По умолчанию `false`, не меняет маршруты |
| `route_ipv6_block` | При активном WDTT блокирует маркированный IPv6, чтобы не обходил туннель |
| `probe_hosts` | Несколько контрольных TCP:443 адресов для оценки прямой сети |

**ВАЖНО про сервер:** если пароль привязан к одному `device_id`, одновременно
использовать его с Android и HAOS не получится. Нужен второй профиль/разрешение
второго устройства на том же сервере; заменять VPS не требуется.

### Как устроена выборочная маршрутизация

В режиме `external` wdttd создаёт `wg-wdtt`, но не устанавливает `full` маршруты.
Когда `route_tailscale: true`, контроллер проверяет `tailscale0`, проверяет
отсутствие конфликтующих таблицы `7477` и приоритета `4990`, после чего
добавляет **только**:

```
ip -4 route add default dev wg-wdtt table 7477
ip -4 rule add pref 4990 fwmark 0x80000/0xff0000 lookup 7477
```

При включённом `route_ipv6_block` дополнительно создаётся недостижимый IPv6
маршрут для того же mark, чтобы исключить обход WDTT по IPv6. Сам маршрут HAOS
по умолчанию не меняется. `SO_MARK 0x80000` характерен для socket-транспорта
Tailscale, однако **его использование следует подтвердить на вашем HAOS**.
Успешная проверка `ip route get ... mark ...` сама по себе не доказывает,
что весь трафик Tailscale действительно помечается.

### Диагностика (только чтение)

В терминале, подключённом к *хостовому* network namespace:

```
ip -4 rule show
ip -4 route show table 7477
ip -4 route get 1.1.1.1 mark 0x80000
ip link show tailscale0
ip link show wg-wdtt
wg show wg-wdtt
```

Если Tailscale недоступен после изменения параметров: через локальный интерфейс
Home Assistant остановите наш аддон (контроллер удаляет правила при корректной
остановке) и верните прежнее значение `userspace_networking` в Tailscale.
После принудительного убийства контейнера возможны остаточные policy rules в
shared network namespace: при запуске контроллер пытается убрать только правила
с собственной точной сигнатурой. При сомнениях проверьте `ip rule show` локально.

## Границы и риски

- Это прототип, **не сертифицированный аддон**, НЕ проверенный на HAOS. Код
  прочитан/проверен статически, но реальные WireGuard/TURN/VPS ещё не испытаны.
- `host_network: true`, `NET_ADMIN`, `NET_RAW` и `apparmor: false` дают аддону
  возможность изменять глобальные сетевые правила HAOS. Устанавливайте только
  если понимаете риск и имеете локальную консоль/доступ.
- У upstream `wdttd` есть OpenWrt-пути и вспомогательные скрипты; включён
  минимальный `datapath` только для `external`. Совместимость с иной версией
  upstream может потребовать исправления.
- DNS и частичная доступность Tailscale/DERP не равны гарантии «белых списков»;
  алгоритм — эвристика. Доступ VK TURN и разрешённость второго девайса должны
  проверяться отдельно.
- При сетевых ограничениях связь может всё равно не заработать: зависит от
  оператора, доступности VK TURN, сервера и протокола.
- Автоматическое удаление policy rule при ошибке не гарантирует восстановление
  Tailscale в любом состоянии. Сохраняйте локальный доступ.
- Не размещайте пароль/WDTT-ссылку в публичном Git репозитории. Настройки
  аддона и резервные копии HAOS могут содержать секреты.

## Проверки исходников и тестов

Контроллер полностью на Python stdlib. Для запуска проверок на ПК:

```
python3 -m unittest discover -s tests -v
python3 -m py_compile wdtt_tailscale/controller.py
```

Исходные проекты: [wdttd](https://github.com/cWDTT/WDTT-OpenWRT),
[original Android WDTT](https://github.com/amurcanov/proxy-turn-vk-android),
[Home Assistant app configuration](https://developers.home-assistant.io/docs/apps/configuration/).

## Веб-панель в Home Assistant (0.3.0)

После запуска приложения нажмите **Открыть веб-интерфейс** в Home Assistant.
Там доступны переключение режимов, настройка VPS/VK/Device ID, эвристика
белых списков, отдельное включение маршрутизации Tailscale и журнал.
Интерфейс работает через **Ingress** на внутреннем порту 8765; отдельный
внешний порт не открывается. Секреты не возвращаются API для чтения.

Настройки из панели хранятся в `/data/ui-overrides.json` (файл внутри
приватной директории данных дополнения), поверх настроек Supervisor.
Для смены сохранённого пароля через интерфейс введите новый; пустое поле
означает «оставить прежний». **Первый запуск рекомендован в режиме `off`**.

Репозиторий включает прототип, но не гарантирует сборку/работу WDTT
на реальном HAOS: нужен тест с VPS и локальным доступом к системе.


### Панель клиента WDTT 0.3.0

Вкладка **Подключение** содержит отдельные поля **IP/домен сервера**,
**порт**, **секрет/пароль**, **VK-хеш №1–4** и постоянный Device ID.
Внутренний `peer` собирается как `IP:PORT`. Секреты скрыты в форме,
не возвращаются в ответах GET API и не выводятся после обновления страницы.
Чтобы заменить список VK-хешей, снова укажите *все* используемые хеши.
Оставленные пустыми секретные поля сохраняют предыдущее значение.

Вкладка **Методы** управляет поддерживаемыми upstream параметрами:
TURN `UDP/TCP`, `audio/video` обфускацией, DNS для VK API, MTU и Workers.
Изменение параметров приводит к перезапуску WDTT-клиента. Наличие выбора
не гарантирует обход конкретных ограничений мобильного оператора.

Вкладка **Терминал** — только безопасные **диагностические команды чтения**
(`wdttd -status`, `ip link`, `ip rule`, `ip route`, `wg show`).
**Произвольные shell-команды в панели запрещены**, так как у аддона есть
`NET_ADMIN` и доступ к сетевому пространству имён хоста. Интерфейс предназначен
для мониторинга Tailscale и WDTT, а не администрирования HAOS.

Вкладка **Авто / Tailscale** управляет эвристикой ограничений мобильной
сети и отдельно разрешает маршрутизацию `fwmark`. По умолчанию
`route_tailscale: false`; не включайте маршруты до проверки рабочего WDTT.

**Публичный репозиторий не должен содержать реальный IP вашего VPS,
секрет или VK-хеши.** В публикации используются только заглушки.


### Интерфейс WDTT (0.3.0)

Панель перерисована по мотивам экранов оригинального WDTT для Android:
тёмная тема, сиреневые переключатели, мобильная нижняя навигация.

- **Туннель:** отдельные поля для IP/домена и порта VPS, четыре поля VK-хешей,
  мощность 9–108, режим VKCalls/legacy (капча), аудио/видео, UDP/TCP, MTU, DNS;
  кнопка «Сохранить и подключить», режимы Выкл/Авто/Всегда.
- **Деплой:** сохранение пароля WDTT и постоянного Device ID. **Нет установки
  VPS по SSH** — это только клиент. SSH-учётные данные не запрашиваются.
- **Исключения:** ручное разрешение маршрутизации *только* транспорта Tailscale,
  защита IPv6, эвристические проверки мобильной сети.
- **Логи:** журнал и фиксированный список безопасных команд диагностики (без shell).
- **Инфо:** сведения о версии и предупреждения безопасности.

Секрет и VK-хеши не возвращаются в API настроек; для изменения четырёх хешей
заполните новый полный набор. **Ни одного реального VPS-адреса, пароля или
VK-хеша в репозитории нет.**

В режиме legacy («Капча») может понадобиться ручное подтверждение; автоматическое
решение CAPTCHA через веб-панель пока не реализовано. Интерфейс не является
дословной копией Android-приложения.
