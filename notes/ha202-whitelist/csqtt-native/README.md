# CSQTT — автономное дополнение HAOS (экспериментальная версия)

Это **не панель управления чужим Docker-контейнером**. Дополнение запускает **собственный** экземпляр `csq-socks` под управлением Home Assistant Supervisor, как Tailscale запускает свой VPN-клиент. Пользователь вводит новую `csqtt://` ссылку в защищённой панели Ingress и управляет своим SOCKS5-соединением без терминала.

## Дизайн

- Базовый образ: **Ubuntu 24.04**, с локально скопированными клиентскими файлами из существующего на HA202 контейнера `csq-socks`. Сеть и основной контейнер `csq-socks` при установке не меняются.
- `host_network: true`, `NET_ADMIN`, `SYS_ADMIN`, `/dev/net/tun` — нужны внутреннему namespace/TUN клиента, аналогично разрешениям Tailscale, **но полный host TUN mode намеренно отключён**.
- Собственный SOCKS5 слушает только **127.0.0.1:11891** на HA202. Никаких маршрутов `ip rule`, `ip route`, default-route и таблицы Tailscale 52 приложение не изменяет. Настройки существующего контейнера не затрагиваются.
- Панель HA Ingress с динамически назначенным портом (`ingress_port: 0`), привязка к внутреннему интерфейсу Supervisor `172.30.32.1` и разрешение запросов только от `172.30.32.2`.
- Авторизация — Home Assistant; в панели есть CSRF-токен. Ссылки не выводятся в журнал или адресную строку. Конфигурация и предыдущая версия хранятся в собственном `/data/csq-socks/` с правами `0600`, попадают в резервные копии HA.
- Сохранение новой ссылки отдельно от подключения. Применение запускает проверку HTTPS через SOCKS. Если она не прошла и есть резервная ссылка — приложение попытается восстановить предыдущую конфигурацию и соединение.
- Дополнительная опция `auto_start` **по умолчанию выключена**. Системные маршруты в этой версии не меняются вообще.

## Ограничения и безопасность

1. **На HA202 уже работает другой контейнер `csq-socks`.** Новое дополнение не выключает его. Для серверов csqtt 2.1 нельзя одновременно использовать один и тот же привязанный к устройству ключ в двух клиентах — используйте отдельную ссылку либо сделайте переход с резервным доступом.
2. `SOCKS5 CONNECT` поддерживает TCP, но **не UDP**. Перевод транспорта Tailscale через этот SOCKS не реализован.
3. Полный TUN в HAOS **не включается** до независимого проверенного watchdog и контроля LAN/KeenDNS/Tailscale.
4. Тест работоспособности `curl` по HTTPS не гарантирует стабильность сервера. Проверяйте длинной серией наблюдений.
5. Доступ `NET_ADMIN`/`SYS_ADMIN` потенциально высокопривилегирован; приложение следует запускать только на доверенном HA202. **Нет `docker_api`, `full_access`, доступа к конфигурации Core и секретам других приложений.**
6. Назначенный порт Ingress читается через Supervisor API. Если Supervisor не выдаст порт, приложение не стартует и не начнёт сетевые операции.
7. При аварийном выключении самого дополнения CSQTT-клиент может требовать ручной уборки его namespace; **это не является независимым механизмом аварийного отката маршрутов**.

## Установка

1. Поместить этот каталог в **`/addons/csqtt_native/` на HA202**. До установки один раз скопировать `/opt/csq-socks` из существующего контейнера `csq-socks` в `/addons/csqtt_native/vendor/csq-socks/` на HA202; сами бинарники **не помещать в публичный GitHub**.
2. В HA202: **Настройки → Приложения/Дополнения → Магазин → ⋮ → Перезагрузить**. Установить «CSQTT — туннель».
3. Запустить приложение, открыть панель **CSQTT**. Вставить `csqtt://…` и нажать «Сохранить ссылку». Затем «Применить и проверить HTTPS».
4. Для приложений, которым нужен прокси, использовать `socks5h://127.0.0.1:11891` **на самом HA202**. Из иных контейнеров это не их `127.0.0.1`.
5. При сбое — «Вернуть прежнюю ссылку» и проверить соединение. Опцию автозапуска включать только после успешных испытаний.

## Перед установкой на HA202

- Проверить, что Tailscale и вход через независимый LAN/KeenDNS работают.
- Проверить, что Supervisor может собрать Ubuntu 24.04 и установить системные зависимости; директория `vendor/csq-socks` копируется с локального старого контейнера, чтобы не зависеть от несуществующего публичного `csq-socks:local`.
- Убедиться, что на HA202 есть интерфейс `hassio` с адресом `172.30.32.1`, что проверено предыдущей диагностикой.
- Не использовать одну csqtt 2.1 ссылку параллельно в двух клиентах.

### Структура

`config.yaml` — настройки дополнения. `Dockerfile` — образ. `manager.py` — Ingress интерфейс и управление собственной копией клиента. `tests/` — локальные unit-тесты логики.

### Замечание по поставке

В публичном репозитории и ZIP **нет клиентских бинарников csqtt**. Это намеренно: они берутся локально из уже установленного на HA202 контейнера. Доступ к Docker Hub нужен только для публичной базы Ubuntu 24.04 и системных пакетов, а не для частного клиента. Автоматическое обновление клиентских бинарников этой экспериментальной версией не реализовано.
