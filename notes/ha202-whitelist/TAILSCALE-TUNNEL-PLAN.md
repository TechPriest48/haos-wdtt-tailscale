# HA202 — поэтапное включение Tailscale в обход

Статус: **план, не инструкция для немедленного применения**. Дата: 2026-11-08.

## Требование

После успешной стабилизации выборочного TUN-обхода пользователь хочет включить в него **и Tailscale**. Это отдельный этап, а не побочный эффект правила `from all`. Нужно отличать:

1. **Трафик приложений через tailnet** (пакеты на `tailscale0`) — важна симметрия возвратного пути и ACL.
2. **Транспорт самого tailscaled** (внешние UDP direct/DERP HTTPS соединения) — чувствителен к маршрутизационным петлям и потере управления.

Перед пилотом каждого класса требуется проверенный не-Tailscale канал управления (локальный LAN/KeenDNS/консоль), запущенный независимый watchdog с проверенным откатом и подтверждённая обратимость.

## Подтверждённые ограничения 8 ноября

- `csq-socks` в текущей поставке содержит SOCKS5 сервер с комментарием `CONNECT only`: команды `UDP ASSOCIATE` он не реализует.
- `ha202-socks-bridge-host` пересылает исключительно TCP через loopback:11990 → Unix-socket; UDP через него не пройдёт.
- Успешный разовый `tun2socks`-тест из прежнего чата не является доказательством поддержки Tailscale UDP.
- Серия наблюдения на HA202: прямой HTTPS 9/9, host-мост SOCKS 6/9. Отдельный последующий тест Cloudflare через обе стороны моста успешно вернул HTTP/2 200, т.е. отказ непостоянен.
- Нынешний `routing-safety.sh` не является надёжным откатом; его проверка `status` в SSH add-on использует BusyBox `ip`, который не принимает table 12022. iproute2 из Tailscale add-on эту таблицу понимает, но сообщает, что она отсутствует.

## Последовательность

### A. Нормальный прямой режим

Все маршруты сохраняются, 52 и правила 5210/5230/5250/5270 не изменяются. `healthcheck-observe.sh` только диагностирует. При отказе прокси прямой режим остается действующим.

### B. Выборочный TUN только для обычного TCP

- Использовать изолированный tun2socks-контейнер и отдельную тестовую цель без перехвата управления.
- Проверить DNS/TLS/HTTP, изоляцию IPv4/IPv6, ответный трафик, задержки и перезапуски контейнера.
- До изменения маршрутов подтвердить независимый watchdog, журнал, идентификатор собственной policy rule, снимок состояния и проверку реального тайм-аута. Не очищать таблицы, если нельзя доказать владение ими.
- При любой проблеме чисто удалить **только** созданные проектом правила и маршруты.

### C. При появлении признаков «белых списков»

- Несколько независимых прямых HTTPS-проверок должны показывать устойчивый отказ.
- Прокси через **host**-мост должен проходить повторные проверки без тайм-аутов и значимых задержек.
- Только после этого включать ограниченное правило для тестовой цели/процесса; проверять переключение туда и обратно, не затрагивая tailnet.

### D. Затем Tailscale в обход по запросу пользователя

1. Сохранить физический LAN/KeenDNS, SSH, известные маршруты к шлюзу, DNS и внешний адрес сервера обхода вне туннеля.
2. Для **Tailscale UDP direct** необходим UDP-совместимый TUN→proxy путь, подтверждённый тестом с UDP-пакетами. Нынешний TCP-only SOCKS не удовлетворяет условию.
3. **DERP HTTPS** потенциально может работать через TCP CONNECT, но это нужно отдельно проверить на используемом Tailscale add-on, включая авторизацию, переподключение и fallback. Нельзя считать доступность DERP по прямому каналу доказательством его работы через прокси.
4. Проверить соединение HA200↔HA202, маршруты, ответные пакеты, перезапуск Tailscale и отказ прокси в пилоте с жёстким сроком отката. Не терять прямой резервный вход во время этих экспериментов.
5. Расширять охват только после успешных испытаний и наблюдения без сбоев.

## Запреты и критерии готовности

- Нет безусловных `from all lookup 12022`, изменения table 52, слепой замены default route и перезапуска сетевых сервисов.
- Не подменять включение Tailscale-трафика включением только приложений на HA202.
- Нужны подтверждённый доступ через независимый канал, проверенный rollback, рабочий UDP-путь **или** испытанный DERP/TCP режим, и воспроизводимо стабильный прокси.

Полезная документация:
- https://github.com/xjasonlyu/tun2socks/wiki/Proxy-Models (SOCKS5 UDP поддерживается **клиентом**, но необходима совместимая UDP-серверная сторона)
- https://tailscale.com/docs/reference/connection-types (direct использует UDP, DERP использует релейное соединение)
